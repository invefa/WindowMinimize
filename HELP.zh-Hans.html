一、概览

WindowMinimize常驻通知区域，不提供主窗口。它注册全局热键，对当前前台窗口执行最小化、跨屏移动和还原。程序本身不注入其它进程，也不修改被操作的窗口，只调用系统提供的窗口接口。

运行需要Windows与.NET8桌面运行时。完整版自带运行时，可以直接运行；Lite版体积小，但要求机器上已安装.NET8桌面运行时。

二、启动与实例

2.1 双击启动

双击可执行文件后没有窗口，只在通知区域出现图标。首次运行会在可执行文件旁写入hotkey.ini，随后按默认热键开始工作。

2.2 重复启动

同一时间只允许一个实例。再次启动时，新进程会把请求转给正在运行的实例，由它打开设置界面，新进程自己退出。以管理员权限运行本程序时，普通权限的第二次启动无法转交请求，会提示已经在运行。

2.3 命令行参数

参数作用
--hotkey指定本次运行的最小化热键，例如--hotkey Win+Q。只影响本次运行，不写回配置文件。
--modeminimize最小化到任务栏，hide直接隐藏窗口。只影响本次运行。
--config使用指定的配置文件，默认可执行文件旁的hotkey.ini。
--lang界面语言，en或zh，默认跟随系统。
--debug强制写入调试日志，等同在设置里开启写入调试日志。
--no-tray不显示托盘图标，供脚本调用。此时失败只写日志，不弹窗。
--help输出用法说明后退出。

参数解析失败时返回退出码2并打印用法；参数正确但已有实例在运行时返回1。

三、托盘图标与菜单

3.1 鼠标操作

左键单击图标打开设置界面。右键打开菜单。图标提示文字显示当前热键与权限级别。

3.2 菜单结构

菜单项作用
版本行显示版本号与当前权限，管理员或普通用户，不可点击。
检查更新立即查询GitHub上的最新稳定版本，结果用气泡或对话框反馈。
隐藏窗口子菜单，列出被隐藏方式收起的窗口，可逐个还原，也可全部还原。用最小化方式收起的窗口不在其中。
热键行显示当前生效的热键，挂起时显示挂起状态，不可点击。
挂起热键切换挂起与恢复。挂起期间热键不响应，托盘图标保持运行。按住Shift点击时挂起5分钟，到点自动恢复。
设置打开设置界面，等同左键单击图标。
打开配置文件用记事本打开当前的配置文件。
重新加载配置立即重新读取配置文件。文件被外部修改时通常不必手动执行，程序会自己发现变化。
开机自动启动开关普通权限的开机自启，写入当前用户的启动项。
以管理员身份开机自启开关管理员权限的开机自启，通过计划任务注册。
以管理员身份重启请求UAC提权并重新启动本程序。已经是管理员时该项不可用。
退出结束程序。历史记录随进程一起消失。

四、热键

4.1 默认热键

动作默认值说明
最小化Win+Q最小化当前前台窗口。
切换屏幕Win+S在原屏幕最小化，再在另一块屏幕准备还原。
还原Win+W还原最近一个进入历史的窗口。

4.2 组合键规则

  • 修饰键为Ctrl、Alt、Shift、Win，加一个主键，用+连接，例如Ctrl+Alt+M。
  • 主键可以是字母、数字、F1到F24、空格、Esc、Enter、方向键等。
  • 不带修饰键时只允许功能键。字母和数字会抢走正常输入，因此被拒绝。
  • F12由Windows保留，不能使用。
  • 系统保留的组合会被拒绝，例如Alt+Tab、Win+L。

4.3 Windows自带的Win组合

Win+Q、Win+S、Win+W这类组合属于系统自身，常规注册接口拿不到。程序改用低级键盘钩子接收这些按键，只转发配置的组合，其余按键照常传给系统。启动提示会说明当前热键是通过钩子生效的。

钩子模式下按键先经过本程序再交给系统，因此响应顺序与常规注册略有不同，两者都是即时响应。

4.4 注册失败

热键被其它程序占用或格式无效时，程序会尝试配置文件里的默认值。仍然失败时，如果不是无托盘模式，会自动打开设置界面，并在提示气泡里说明原因。具体的失败信息写入日志。

4.5 挂起

挂起后三个热键同时停止响应，适合临时让其它程序占用这些按键。挂起状态在托盘菜单第一行可以看到，点击菜单项或在设置里保存都会恢复。

五、最小化

5.1 目标窗口

目标是当前前台窗口的最顶层窗口。以下情况按一次空触发处理，不做任何操作：前台窗口不可见、前台是任务栏或桌面、前台是开始菜单与搜索界面、前台是本程序自己的窗口。这样在桌面上误按热键不会产生副作用。

5.2 最小化到任务栏

调用标准的窗口最小化接口，窗口进入任务栏，位置记忆保留。还原后窗口回到原来的屏幕与位置。

5.3 直接隐藏窗口

窗口离开屏幕，同时从任务栏移除。隐藏的窗口不会出现在任务栏或Alt+Tab，需要通过托盘菜单的隐藏窗口子菜单还原。这种方式适合把窗口真正收起来，代价是必须回到托盘才能找回。

5.4 首次无效时的重试

部分窗口会忽略第一次最小化请求。程序在请求后等待350毫秒复查，仍未最小化就再请求一次；仍然无效时，把窗口强制前置后再次最小化。还原操作会取消这个后台重试，避免窗口刚还原又被最小化。

六、切换屏幕

6.1 过程

  1. 在窗口当前所在的屏幕完成最小化，最小化动画留在原屏幕。
  2. 等最小化动画结束后，记录窗口在工作区中的相对位置。
  3. 按同样的相对位置，把窗口的还原位置和任务栏按钮放到目标屏幕。
  4. 还原动画按目标屏幕准备，还原时窗口直接出现在目标屏幕。

整个过程看不到窗口跨越屏幕的画面，也看不到任务栏按钮先消失再出现的跳变。

6.2 屏幕配对

设置里的屏幕A与屏幕B决定移动方向：窗口在A上时送到B，在B上时送到A，在其它屏幕上时送到B。只接一块屏幕时热键仍然可用，来源与目标相同，效果等同普通最小化。

屏幕以设备名保存，显示器热插拔后重新接回同一块屏幕仍能匹配。

6.3 位置保持

窗口不按绝对坐标搬动，而是按它在原工作区中的相对位置换算到目标工作区。两块屏幕分辨率不同时，窗口落在目标屏幕的对应位置，不会跑到屏幕外。窗口尺寸不变。

七、还原与历史

7.1 历史

每次最小化都会把窗口压入历史，还原热键弹出最近一个。历史保存在内存中，退出程序后清空。窗口已经关闭时会被跳过。

7.2 记录所有程序

默认只记录本工具最小化的窗口。开启记录所有程序的最小化窗口后，通过任务栏、其它程序或系统最小化的窗口也会进入历史。开启时会把当时已经最小化的窗口一并加入。没有标题的窗口和系统外壳窗口不会被记录，避免还原到无意义的对象。

7.3 还原动效

选项行为
原生动画使用系统的还原动画。
淡入窗口在目标位置直接出现，伴随短暂淡入。
关闭动效不使用动画，立即出现。
系统默认交给系统决定。

只有切换过屏幕的窗口才按这里的设置还原。普通最小化的窗口总是使用原生动画，避免在同一块屏幕上还原时出现位置跳变。

八、设置界面

8.1 打开方式

左键单击托盘图标，或在托盘菜单选择设置。设置界面打开期间，当前热键继续工作。

8.2 热键录入

  • 点击热键输入框后直接按下组合键，不需要手动输入文本。
  • 只有输入框有焦点、并且设置窗口是活动窗口时才接收按键。
  • 点击界面其它位置、切到别的窗口或关闭窗口都会立即停止接收，不会在后台吞掉按键。
  • Esc取消本次录入并恢复原值，Backspace与Delete清空，右侧X按钮同样清空。
  • 输入框为空时显示按下快捷键的占位提示。

8.3 冲突检测

三个热键中任意两个相同就无法保存，界面在底部提示重复的组合并保留对话框。被Windows保留或被其它程序占用的组合在录入时就会被拒绝；保存后若注册失败，托盘仍然会给出提示。

8.4 各项含义

启动时检查更新启动后查询GitHub上的新版本。

鼠标停在任意一行上会显示该行的简短说明。保存按钮把当前值写入配置文件并立即应用，不需要重启。

九、配置文件

9.1 位置

默认是可执行文件旁的hotkey.ini。该目录不可写时，改用%APPDATA%\WindowMinimize\hotkey.ini。

9.2 键

键默认值含义
HotkeyWin+Q最小化热键。
MoveHotkeyWin+S切换屏幕热键。
RestoreHotkeyWin+W还原热键。
Modeminimizeminimize或hide。
MonitorA空屏幕A的设备名，留空自动选择。
MonitorB空屏幕B的设备名，留空自动选择。
RestoreAnimationnativenative、fade、disable或default。
TrackAllMinimizedfalse是否记录所有程序的最小化窗口。
CheckUpdatestrue启动时是否检查更新。

旧配置只有Hotkey时，程序沿用该值作为最小化热键，其余键补上默认值。旧版把Win+S当作最小化热键，升级后该组合改作切换屏幕热键。

9.3 生效方式

保存后立即生效。程序监视配置文件的变化，外部编辑保存后会自动重新加载，不需要重启。托盘菜单的重新加载配置用于手动触发。文件写坏导致解析失败时，失败项保持原值并写入日志，其余项照常应用。

十、更新

10.1 检查时机

启动时自动检查，可在设置里关闭；也可以随时从托盘菜单手动检查。

10.2 版本来源与匹配

查询的是GitHub仓库invefa/WindowMinimize的最新稳定Release。程序按当前使用的是完整版还是Lite版，选取对应的资产文件。

10.3 校验

Release提供SHA256SUMS.txt时，程序先下载校验文件，核对下载文件的SHA-256，不一致就放弃本次更新并报错。

10.4 安装

  1. 下载到%LOCALAPPDATA%\WindowMinimize\updates。
  2. 确认后退出程序，启动一个独立的PowerShell脚本。
  3. 脚本最多等60秒让进程结束，然后复制新文件覆盖可执行文件。
  4. 脚本重新启动程序，过程写入%LOCALAPPDATA%\WindowMinimize\update.log。

自动安装更新打开时，发现新版本不再询问，直接走上面的流程。

10.5 失败处理

网络不可用、没有匹配的资产、校验失败、文件被占用都会给出提示。此时当前版本继续运行，配置与历史不受影响。可执行文件所在目录不可写时，替换会失败，需要把程序放到有写权限的目录后重新更新。

十一、权限

11.1 前台是管理员权限窗口

Windows不会把热键发给普通权限进程，当前台是管理员权限窗口时热键没有反应。需要处理这类窗口时，以管理员权限运行本程序。权限提示气泡会说明这一情况。

11.2 管理员自启

以管理员身份开机自启通过计划任务注册，任务名与程序名相同。登录时由任务计划程序以最高权限启动，不经过UAC确认。

11.3 提权重启

托盘菜单的以管理员身份重启会请求UAC，确认后结束当前进程并以管理员权限重新启动。取消UAC不会影响正在运行的实例。

十二、日志与通知

12.1 调试日志

开启写入调试日志后，详细信息写入可执行文件同目录的hotkey.log，每次启动覆盖上一次的内容。日志记录热键注册结果、每次操作的目标窗口与结果、更新流程。命令行参数--debug可以临时打开。

12.2 通知气泡

提示分三类，可分别关闭：启动提示说明热键是否生效以及生效方式；错误提示在操作失败时出现；权限提示在窗口需要更高权限时出现。关闭某一类不影响日志记录。

十三、这份文档

标题栏的问号按钮打开这份文档。文档随程序内嵌，首次打开时解包到%LOCALAPPDATA%\WindowMinimize\help；升级后内容有变化会替换旧副本，不会停留在旧版本。

右上角的配色选择器提供跟随系统、浅色、深色三档，默认跟随系统。选择结果保存在浏览器本地，下次打开保持。文档不写死颜色，深浅两态都取自系统色。

十四、常见问题

热键没有反应

先看托盘菜单里的热键行是否显示挂起，再确认前台窗口是不是管理员权限窗口。都不是的话，打开写入调试日志后复现一次，日志里会有注册结果与被忽略的原因。

隐藏的窗口找不回来

隐藏方式收起的窗口不在任务栏，也不在Alt+Tab，只能从托盘菜单的隐藏窗口子菜单还原。改用最小化到任务栏可以避免这种情况。

还原热键跳过了某个窗口

该窗口可能没有被记录。默认只记录本工具最小化的窗口，开启记录所有程序的最小化窗口后才会包含其它来源。已经关闭的窗口也会被跳过。

切换屏幕后位置不对

窗口按在原工作区的相对位置换算。如果两块屏幕的工作区差异很大，例如任务栏位置不同，换算结果会跟着变化。调整屏幕A与屏幕B的选择可以固定移动方向。

升级后打开的仍是旧文档

程序会比较解包副本与内嵌文档的内容，不一致时替换。若目录不可写，删除%LOCALAPPDATA%\WindowMinimize\help后重新打开即可。

配置保存在可执行文件旁的hotkey.ini；该目录不可写时使用%APPDATA%\WindowMinimize。日志与更新文件位于%LOCALAPPDATA%\WindowMinimize。
