WindowMinimize

1. Overview

WindowMinimize sits in the notification area and provides no main window. It registers global hotkeys that minimize the foreground window, move it to another screen, and restore it later. The program does not inject into other processes and does not modify the windows it acts on; it only calls the window interfaces Windows offers.

It needs Windows and the .NET 8 desktop runtime. The full build carries the runtime and runs as is; the lite build is small but expects the .NET 8 desktop runtime to be installed.

2. Starting and single instance

2.1 Double click

Starting the executable shows no window, only a tray icon. The first run writes hotkey.ini next to the executable and then starts working with the default hotkeys.

2.2 Starting twice

Only one instance runs at a time. A second start forwards a request to the running instance, which opens its settings dialog, and the new process exits. When the running instance is elevated, a normal-privilege second start cannot forward the request and reports that the program is already running.

4. Hotkeys

4.1 Defaults

ActionDefaultNotes
MinimizeWin+QMinimize the foreground window.
Move to the other screenWin+SMinimize on the source screen, prepare the restore on the other one.
RestoreWin+WRestore the window that entered the history last.

4.2 Combination rules

  • A modifier among Ctrl, Alt, Shift and Win plus one main key, joined with +, for example Ctrl+Alt+M.
  • The main key can be a letter, a digit, F1 to F24, Space, Esc, Enter, an arrow key and so on.
  • Without a modifier only function keys are allowed. Letters and digits would steal normal typing and are rejected.
  • F12 is reserved by Windows and cannot be used.
  • System combinations such as Alt+Tab and Win+L are rejected.

4.3 Windows-owned Win combinations

Combinations such as Win+Q, Win+S and Win+W belong to the system and cannot be taken through the regular registration call. The program listens with a low-level keyboard hook instead, forwards only the configured combination, and passes every other key on to Windows. The startup balloon states when a hotkey works through the hook.

In hook mode the key reaches this program before Windows, so the ordering differs slightly from a registered hotkey. Both respond immediately.

4.4 Registration failure

When another program holds the hotkey or the text is invalid, the program falls back to the default from the configuration file. If that fails too and the tray icon is enabled, the settings dialog opens and a balloon explains the reason. The details go to the log.

4.5 Suspension

Suspending stops all three hotkeys at once, which is useful when another program needs those keys for a while. The tray menu shows the state in the hotkey row; clicking the menu item or saving the settings restores the hotkeys.

5. Minimizing

5.1 Target window

The target is the top-level window of the current foreground window. These cases are treated as an empty trigger and do nothing: the foreground window is not visible, the foreground is the taskbar or the desktop, the foreground is the Start menu or search, or the foreground belongs to this program. Pressing the hotkey on the desktop therefore has no side effect.

5.2 Minimize to the taskbar

The standard minimize call is used, so the window enters the taskbar and keeps its placement. Restoring it returns it to the original screen and position.

5.3 Hide the window

The window leaves the screen and is removed from the taskbar. A hidden window appears in neither the taskbar nor Alt+Tab, so it has to be restored from the hidden windows submenu. This mode really puts a window away; the cost is that the tray menu is the only way back.

5.4 Retry when the first request is ignored

Some windows ignore the first minimize request. The program checks again after 350 milliseconds and asks once more, and if that also fails it brings the window to the front and minimizes it again. A restore cancels this background retry, so a window is not minimized again right after being restored.

6. Screen switching

6.1 Sequence

  1. Minimize the window on the screen it currently occupies; the minimize animation stays there.
  2. Once the animation has finished, record the window position relative to the work area.
  3. Place the restore position and the taskbar button on the target screen at the same relative position.
  4. Prepare the restore animation for the target screen, so the window appears there directly.

The window is never seen crossing between screens, and the taskbar button does not visibly disappear and reappear.

6.2 Screen pairing

Screen A and Screen B in the settings decide the direction: a window on A goes to B, a window on B goes to A, and a window on any other screen goes to B. With a single screen the hotkey still works; source and target are the same, so it behaves like a plain minimize.

Screens are stored by device name, so a monitor that is unplugged and reconnected is still recognized.

6.3 Position

The window is not moved by absolute coordinates. Its relative position in the source work area is mapped onto the target work area, so the window lands at the corresponding place even when the screens differ in resolution, and it does not end up off-screen. The window size does not change.

7. Restoring and history

7.1 History

Every minimize pushes the window onto the history and the restore hotkey pops the most recent one. The history lives in memory and is cleared when the program exits. Windows that no longer exist are skipped.

7.2 Recording all programs

By default only windows minimized by this tool are recorded. With the all-programs option enabled, windows minimized from the taskbar, from another program or by the system also enter the history, and windows already minimized at that moment are collected too. Windows without a title and shell surfaces are never recorded, so the restore hotkey does not target meaningless objects.

7.3 Restore animation

OptionBehaviour
NativeThe system restore animation.
FadeThe window appears at its target position with a short fade.
DisabledNo animation, the window appears at once.
System defaultLeave the choice to the system.

Only windows that were moved to another screen use this setting. A plain minimize always restores with the native animation, which keeps the window from jumping inside the same screen.

8. Settings dialog

8.1 Opening it

Left click the tray icon, or choose Settings in the tray menu. The hotkeys keep working while the dialog is open.

8.2 Entering a hotkey

  • Click a hotkey field and press the combination; typing the text by hand is not needed.
  • Keys are captured only while the field has focus and the dialog is the active window.
  • Clicking elsewhere in the dialog, switching to another window or closing the dialog stops capturing at once, so keys are never swallowed in the background.
  • Esc cancels the entry and restores the previous value, Backspace and Delete clear it, and the X button on the right clears it as well.
  • An empty field shows a placeholder telling you to press a shortcut.

8.3 Conflict detection

Two of the three hotkeys cannot hold the same combination: saving is refused, the dialog stays open and the duplicate is named at the bottom. Combinations reserved by Windows or held by another program are rejected while pressing them. If registration fails after saving, the tray still reports it.

A configuration that only carries Hotkey keeps that value as the minimize hotkey and takes defaults for the rest. Earlier versions used Win+S as the minimize hotkey; after an upgrade that combination becomes the screen switching hotkey.

9.3 When changes apply

Saving applies immediately. The program watches the file, so an external edit is picked up without a restart; the tray item reloads it by hand. When parsing fails, the affected keys keep their previous values and the failure is logged, while the remaining keys still apply.

10. Updates

10.1 Timing

Checked at startup unless disabled in the settings, and on demand from the tray menu.

10.2 Source and file matching

The latest stable release of the GitHub repository invefa/WindowMinimize is queried. The program picks the asset that matches the build in use, full or lite.

10.3 Verification

When the release carries SHA256SUMS.txt, the program downloads it first and compares the SHA-256 of the downloaded file. A mismatch aborts the update with an error.

10.4 Installation

  1. The file is downloaded to %LOCALAPPDATA%\WindowMinimize\updates.
  2. After confirmation the program exits and starts a detached PowerShell script.
  3. The script waits up to 60 seconds for the process to end, then copies the new file over the executable.
  4. The script starts the program again and writes the outcome to %LOCALAPPDATA%\WindowMinimize\update.log.

With automatic installs enabled the confirmation is skipped and the sequence runs directly.

10.5 Failures

An unreachable network, no matching asset, a failed checksum and a locked file each produce a message. The current version keeps running and neither the configuration nor the history is affected. When the folder holding the executable is not writable the replacement fails, so the program has to live in a writable folder to update itself.

11. Permissions

11.1 An elevated window in front

Windows does not deliver hotkeys to a standard-privilege process while an elevated window is in front, so the hotkey does nothing in that situation. Run the program as administrator to handle those windows. The permission balloon explains this case.

11.2 Elevated autostart

Elevated autostart is registered as a scheduled task with the same name as the program. At logon the task scheduler starts it with the highest privileges, without a UAC prompt.

11.3 Restarting elevated

The tray item requests UAC and, after confirmation, ends the current process and starts an elevated one. Cancelling the prompt leaves the running instance untouched.

12. Log and notifications

12.1 Debug log

With the debug log enabled, detail goes to hotkey.log next to the executable, and each start replaces the previous content. The log records hotkey registration results, the target window and outcome of every action, and the update sequence. The command line option --debug turns it on for one run.

12.2 Notification balloons

There are three categories that can be switched separately: the startup notice states whether the hotkeys are active and how they are registered; the error notice appears when an action fails; the permission notice appears when a window needs higher privileges. Turning a category off does not affect the log.

13. This document

The question mark in the title bar opens this document. It ships inside the executable and is unpacked to %LOCALAPPDATA%\WindowMinimize\help on first use; after an upgrade a changed document replaces the old copy instead of leaving it behind.

The colour scheme picker at the top right offers System, Light and Dark, System by default. The choice is kept in the browser. The document defines no fixed colours; both schemes come from system colours.

14. Troubleshooting

The hotkey does nothing

Check the hotkey row in the tray menu for a suspended state, then check whether the foreground window is elevated. If neither applies, enable the debug log, reproduce the case and read the log; it records the registration result and the reason a trigger was ignored.

A hidden window cannot be found

A window hidden with the hide mode is in neither the taskbar nor Alt+Tab; it can only be restored from the hidden windows submenu. Switching to the minimize mode avoids the situation.

The restore hotkey skips a window

That window was probably not recorded. Only windows minimized by this tool are recorded by default; enable the all-programs option to include other sources. Windows that have been closed are skipped as well.

The position is wrong after a screen switch

The relative position in the source work area is mapped onto the target work area, so very different work areas, for example with the taskbar on another edge, shift the result. Choosing screen A and screen B explicitly fixes the direction.

An upgrade still shows the old document

The unpacked copy is compared with the embedded document and replaced when it differs. If the folder is not writable, delete %LOCALAPPDATA%\WindowMinimize\help and open the document again.

Configuration lives in hotkey.ini next to the executable, or under %APPDATA%\WindowMinimize when that directory is not writable. Logs and update files live under %LOCALAPPDATA%\WindowMinimize.
